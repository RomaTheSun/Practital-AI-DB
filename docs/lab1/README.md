## Метод

Набір `data/golden.jsonl` (`dataset_sha256=f12b72c7837d4bea812f26b6f58cc5cca5559aa0f4b90720b36567b8524c0f7b`) заздалегідь поділено на `dev` (8), `test` (25) і зафіксовану хмарну підмножину `q15` (15). Промпти налаштовувалися лише на `dev`; `test` і `q15` використовувалися тільки для звітування. Після dev-перевірки всі промпти й чотири гіпотези зафіксовано комітом `2cc4a1c` до першого тестового рядка; кожен результат містить SHA цього коміту та SHA-256 конкретного промпту.

Порівнюються `v0` (zero-shot), `v1` (роль, правила, JSON), `v2` (`v1` плюс усі 8 `dev` few-shot) і `v4` (теги `<input>`, екранування `</input>`, правило недовіреного вводу). Локальна `qwen3:4b` працює через Ollama з фактичним контекстом 16 384, `temperature=0`, `seed=7`, `reasoning_effort=high`, `max_tokens=4096`; вона пройшла весь `test` 2026-10-27. Активна хмарна умова — OpenAI `gpt-6-luna` через Chat Completions з `reasoning_effort=none`; усі чотири версії пройшли `q15` 2026-11-07–09 з 15/15 правильними відповідями кожна. Історичні Gemini-рядки збережено окремо лише для provenance.

`score.py` детерміновано прибирає `<think>` і JSON-огорожі, спершу читає `{"label": ...}`, потім однозначну жирну мітку, потім рівно одну різну допустиму мітку в тексті. `correct` — нормалізований точний збіг із `expected`; дві різні мітки або відсутня фінальна мітка дають `None`. Парсер і тести були закомічені до `test`, після прогонів `correct` не перераховувався. Рядки 429/5xx/timeout не входять у знаменник, а `--resume` пропускає кожен ID з успішною спробою.

Для accuracy звітуються `k/n` і двобічний 95% інтервал Вілсона; через малий `n` варіант не називається кращим, якщо інтервали перетинаються. Додатково порівнюються `hard`, окремі приклади `injection`, flips відносно `v0`, valid rate, токени, медіана затримки й оцінена вартість. Сирі локальні результати зафіксовано комітом `174910d0fc4d39af0948cff0e7a2e6f6a1082a02`, а хмарні GPT-6 Luna — комітами `b5cf640`, `f319ffb` і `dcd2634`.

Відхилення від протоколу: перші історичні Gemini-прогони були обмежені free-tier і 503; вони не використовуються для фінального порівняння. 2026-11-07 до стенду додано GPT-6 Luna: timeout OpenAI SDK — 180 с, внутрішні повтори вимкнено (`max_retries=0`), а runner має `--retry-attempts 1`. Денний ліміт 50 RPD зупиняв часткові прогони, які було безпечно завершено через `--resume` після відновлення квоти. Параметри моделі, промпти й scoring не змінювалися між частинами одного прогону.

## Крок 04 · Структуровані відповіді

Клієнт v2 зводить Chat Completions і Responses API до одного `Turn`; схему `StorageLabel` перевіряє Pydantic незалежно від гарантій сервера. [A/B-порівняння](structured.md) завершено для локальної моделі на 25+25 відповідях і GPT-6 Luna на 15+15: відповідно 24/25 та 15/15 правильних у кожному режимі. Responses API успішно перевірено окремим B-запитом зі строгою схемою.

## Результати

- [Токени ua/en](basics.md#токени-множник-uaen): для `qwen3:4b` медіанний множник становить 2,54, IQR 2,36–2,86.
- [Вибірка і міркування](basics.md): `temperature=0`, `seed=7` дали 1/10 різних відповідей; reasoning `high` — 9/10 правильних проти 0/10 у `none`.
- [Промпти](prompts.md): локальні `v2` і `v4` дали 24/25, але їхні 95% ДІ перетинаються з `v1`; обрано коротший `v4` із 7/7 на `hard`.
- [Структуровані відповіді](structured.md): локально режими A і B дали по 25/25 валідних та 24/25 правильних; GPT-6 Luna — по 15/15 валідних і правильних.
- [Інструменти](tools.md): локально й GPT-6 Luna tools підняли точність із 4/8 до 8/8; для GPT-6 Luna усі 10 викликів мали валідні аргументи.

## Рішення

1. Модель: `qwen3:4b` (`model_reported`) · локальний Ollama · дата головного прогону: 2026-10-27.
2. Версія промпту: `v4`, `prompt_sha256` `10adc222fad1`.
3. Режим API: A через `openai_chat`; для звичайної класифікації без tools, а для залежних від довідників кейсів — ручний цикл із `lookup_workload` та `lookup_requirement`.
4. Числа з власних таблиць:
   - точність 24/25 = 0,96, 95% ДІ [0,80; 0,99] — [абляція](prompts.md#абляція);
   - валідні відповіді 25/25; структурований режим B також дав 25/25, але не змінив точність 24/25 — [A/B](structured.md#режим-a-проти-режиму-b);
   - медіанна затримка `v4` — 41 915 мс, середній вхід — 659,52 токена, середній вихід — 832,68 токена; локальна API-вартість — $0 — `results/03-v4-local.jsonl`;
   - у залежних від зовнішніх даних кейсах tools підняли точність із 4/8 до 8/8 — [таблиця tools](tools.md#з-інструментами-і-без).
5. Компроміс: локальна модель не передає навіть синтетичні описи провайдеру й не має API-тарифу, але одна відповідь займає десятки секунд і використовує ресурси ноутбука. GPT-6 Luna дала 15/15 у всіх хмарних версіях промпту й 8/8 з tools, проте має API-вартість і RPD-квоту облікового запису.
6. Рішення переглядається, якщо новий незалежний test покаже accuracy нижче 0,90, зміниться digest `qwen3:4b`, медіанна затримка перевищить 60 с або GPT-6 Luna покаже інший результат на зафіксованому незалежному наборі.

## Загрози валідності

| Загроза | Власне число | Пом'якшення |
|---|---|---|
| Конфігурацію обрано на тому самому `test`, на якому звітую | `v4` 24/25 [0,80; 0,99], `v2` 24/25 [0,80; 0,99], `v1` 23/25 [0,75; 0,98] | називати оцінку оптимістичною; перевірити `v4` на новій зафіксованій вибірці до курсової |
| Усі входи синтетичні | 33/33 входів створено ШІ; 33/33 міток особисто підтверджено | додати публічні реальні описи архітектур із ліцензією та звітувати точність окремо |
| Мала вибірка | локальний `n=25`, хмарний `q15`; ширина ДІ для 24/25 — 0,19 | не заявляти перевагу при перетині ДІ; збільшити test і робити paired-порівняння на спільних ID |
| Помилки API поза знаменником | GPT-6 Luna тимчасово зупинялася на 50 RPD; усі необхідні кроки 03–05 зрештою завершені через `--resume` | показувати помилки окремо, продовжувати лише через `--resume`, не трактувати часткові n як фінальний рейтинг |
| Недетермінованість і версія сервера | при `temperature=1` без seed отримано 10/10 різних відповідей, із `seed=7` — 1/10 | фіксувати seed, digest/ID моделі й повторювати критичні конфігурації |
