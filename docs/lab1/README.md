## Метод

Набір `data/golden.jsonl` (`dataset_sha256=f12b72c7837d4bea812f26b6f58cc5cca5559aa0f4b90720b36567b8524c0f7b`) заздалегідь поділено на `dev` (8), `test` (25) і зафіксовану хмарну підмножину `q15` (15). Промпти налаштовувалися лише на `dev`; `test` і `q15` використовувалися тільки для звітування. Після dev-перевірки всі промпти й чотири гіпотези зафіксовано комітом `2cc4a1c` до першого тестового рядка; кожен результат містить SHA цього коміту та SHA-256 конкретного промпту.

Порівнюються `v0` (zero-shot), `v1` (роль, правила, JSON), `v2` (`v1` плюс усі 8 `dev` few-shot) і `v4` (теги `<input>`, екранування `</input>`, правило недовіреного вводу). Локальна `qwen3:4b` працює через Ollama з фактичним контекстом 16 384, `temperature=0`, `seed=7`, `reasoning_effort=high`, `max_tokens=4096`; вона пройшла весь `test` 2026-10-27. Хмарна `gemini-3.8-flash` має `reasoning_effort=low` і проходить `q15`: 2026-10-27 отримано 18 успішних відповідей, 2026-10-29 — ще 12, 2026-11-01 — ще 16, 2026-11-02 — ще 2; разом 48 із потрібних 60. Free tier повідомляє добовий ліміт 20 запитів; перервані генерації, повтори після 503 та запити, що отримали 429, також витрачають доступну кількість спроб.

`score.py` детерміновано прибирає `<think>` і JSON-огорожі, спершу читає `{"label": ...}`, потім однозначну жирну мітку, потім рівно одну різну допустиму мітку в тексті. `correct` — нормалізований точний збіг із `expected`; дві різні мітки або відсутня фінальна мітка дають `None`. Парсер і тести були закомічені до `test`, після прогонів `correct` не перераховувався. Рядки 429/5xx/timeout не входять у знаменник, а `--resume` пропускає кожен ID з успішною спробою.

Для accuracy звітуються `k/n` і двобічний 95% інтервал Вілсона; через малий `n` варіант не називається кращим, якщо інтервали перетинаються. Додатково порівнюються `hard`, окремі приклади `injection`, flips відносно `v0`, valid rate, токени, медіана затримки й оцінена вартість. Сирі локальні результати та першу порцію Gemini зафіксовано комітом `174910d0fc4d39af0948cff0e7a2e6f6a1082a02`.

Відхилення від протоколу: першу хмарну порцію запущено чотирма однопотоковими процесами паралельно, після чого добова квота була вичерпана; її затримки не використовуються для порівняння. OpenAI-сумісний клієнт має timeout 900 секунд, а добове `quota exceeded` більше не повторюється раннером. Після третьої порції перший добовий 429 також зупиняє весь поточний прогін. 2026-11-02 чотири записані помилки 503 через внутрішні повтори раннера витратили більшість квоти; після цього додано `--retry-attempts 1`. 2026-11-05 виявлено, що нативний SDK мав власні типові 5 спроб і не мав явного timeout; тепер `HttpRetryOptions(attempts=1)` вимикає їх, а `HttpOptions(timeout=180000)` обмежує один native-запит трьома хвилинами. Параметри моделі, промпти й scoring не змінювалися. Незавершені хмарні значення в таблиці позначають лише прогрес, а не фінальний результат.

## Крок 04 · Структуровані відповіді

Клієнт v2 зводить OpenAI-сумісну й нативну Gemini-форми до одного `Turn`; схему `StorageLabel` перевіряє Pydantic незалежно від гарантій сервера. [Локальне порівняння A/B](structured.md) завершено на 25+25 відповідях: обидва режими мають 25/25 валідних, 24/25 правильних і ту саму змістову помилку `t20`. Нативний Gemini перевірено живим запитом A (1/1); 2026-11-03 наступні 19 запитів дали 18 серверних 503 і один хвилинний 429, тому хмарні A/B лишаються незавершеними.

## Результати

- [Токени ua/en](basics.md#токени-множник-uaen): для `qwen3:4b` медіанний множник становить 2,54, IQR 2,36–2,86.
- [Вибірка і міркування](basics.md): `temperature=0`, `seed=7` дали 1/10 різних відповідей; reasoning `high` — 9/10 правильних проти 0/10 у `none`.
- [Промпти](prompts.md): локальні `v2` і `v4` дали 24/25, але їхні 95% ДІ перетинаються з `v1`; обрано коротший `v4` із 7/7 на `hard`.
- [Структуровані відповіді](structured.md): локально режими A і B дали по 25/25 валідних та 24/25 правильних; схема не виправила змістову помилку `t20`.
- [Інструменти](tools.md): локально 8/8 із tools проти 4/8 без них; усі 9 викликів мали валідні аргументи.

## Рішення

1. Модель: `qwen3:4b` (`model_reported`) · локальний Ollama · дата головного прогону: 2026-10-27.
2. Версія промпту: `v4`, `prompt_sha256` `10adc222fad1`.
3. Режим API: A через `openai_chat`; для звичайної класифікації без tools, а для залежних від довідників кейсів — ручний цикл із `lookup_workload` та `lookup_requirement`.
4. Числа з власних таблиць:
   - точність 24/25 = 0,96, 95% ДІ [0,80; 0,99] — [абляція](prompts.md#абляція);
   - валідні відповіді 25/25; структурований режим B також дав 25/25, але не змінив точність 24/25 — [A/B](structured.md#режим-a-проти-режиму-b);
   - медіанна затримка `v4` — 41 915 мс, середній вхід — 659,52 токена, середній вихід — 832,68 токена; локальна API-вартість — $0 — `results/03-v4-local.jsonl`;
   - у залежних від зовнішніх даних кейсах tools підняли точність із 4/8 до 8/8 — [таблиця tools](tools.md#з-інструментами-і-без).
5. Компроміс: локальна модель не передає синтетичні описи провайдеру й не має API-тарифу, але одна відповідь займає десятки секунд і використовує ресурси ноутбука. Gemini швидший і дав 15/15 на завершених `v0` та `v1`, проте free tier може використовувати дані для поліпшення продуктів, має добову квоту й фактично був недоступний через 503.
6. Рішення переглядається, якщо новий незалежний test покаже accuracy нижче 0,90, зміниться digest `qwen3:4b`, медіанна затримка перевищить 60 с або Gemini стане стабільно доступним. Для ціни Gemini після 31.12.2026 треба перерахувати таблиці командою `uv run python scripts/report.py --price gemini=1.50/7.50 --price gemini-native=1.50/7.50`.
