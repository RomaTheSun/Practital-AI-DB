## Висновок

- Режим A описує той самий JSON лише в промпті, а режим B додатково передає нативну схему. В обох режимах стенд перевіряє відповідь класом `StorageLabel` із забороною зайвих полів.
- Ollama дав 25/25 валідних відповідей і в A, і в B. Документація не описує механізм декодування, тому звіт не приписує цей результат конкретній граматиці: він підтверджений лише фактичними рядками.
- Обидва режими дали 24/25 правильних і 1/25 «валідно, але хибно»: `t20` повернув `postgresql` замість `redis`. Схема гарантує форму, але не правильність мітки.
- У режимі A `score.clean` прибирає суцільну Markdown-огорожу `json` і блоки `<think>…</think>` перед Pydantic-валідацією. Між прогонами A і B очищення не змінюється.
- На 25 спільних ID немає жодного flip правильності й жодної дослівної зміни `output_raw`. Середній вихід — 833 токени в A проти 830 у B; усі `finish_reason=stop`. Для цієї моделі й вибірки нативна схема не змінила зміст, бо промпт уже забезпечив 100% валідність. Для GPT-6 Luna Chat Completions режими A і B завершено з 15/15 валідних і правильних у кожному; строгість схеми не змінила correctness на цій вибірці. Responses API також успішно перевірено в B на одному `q15` прикладі.
- 2026-11-03 після скидання квоти 19 нативних A-запитів не дали нових відповідей: 18 завершилися `503 high demand`, один — хвилинним `429` при ліміті RPM=5. Повтори були вимкнені; B не запускався, щоб зберегти один запит денного резерву.
- 2026-11-04 ще 14 A-запитів із темпом 4 RPM і без повторів також завершилися `503 high demand`. Хмарне A/B усе ще має лише одну успішну A-відповідь, тому висновок про різницю режимів робити не можна.
- 2026-11-05 перший контрольний native-запит завис усередині типових SDK-retries і був перерваний без рядка результату; після додавання 180-секундного timeout та `attempts=1` повторний одиничний запит за 8 секунд повернув `503 high demand`. Решту квоти збережено.

## Чому це може не відтворитися

- Ollama може змінити реалізацію `response_format`; документація підтверджує приймання JSON Schema, але не описує механізм декодування.
- Навіть за фіксованих параметрів версія сервера, модель або квантування можуть змінити відповідь.
- На малому наборі різниця між A і B може бути нульовою; це не доводить загальну еквівалентність режимів.
- Chat Completions і Responses API мають різні поля, облік токенів та причини завершення; стенд зводить їх до спільного `Turn`, але серверні зміни можуть вплинути на результат.
- Доступність конкретної preview-моделі залежить від поточного навантаження: серія 503 може не відтворитися в інший час навіть із тим самим ключем і запитом.
